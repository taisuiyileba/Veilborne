### 服务端测试

`gametest-88-pass.log`：88 项必需 GameTest 全部通过，在最终源码上运行。新增 `skiffCatchesUpInsteadOfLeaping`：小舟被屋顶挡住两百刻后撤掉屋顶，它要离开原地，而且每刻最多走 0.3 格，不能一步跳回航线。

### 自然触发的完整流程

- 失路叶鱼停在小木屋的玻璃窗外；拿着花退到露天，它们汇成金鱼、落下金叶，得到记录。

前几轮运行中发现并修正的问题：

- **测试脚本自己清空了背包：** “拿着花”的步骤原先会清空整个背包再把花放进主手，把手记、围场的饱满梦种和礼物都丢了；等巨鹿时也清过一次背包。改为把花放在副手（叶鱼与梦种认两只手），背包保留赢得的东西。
- **礼物被直接捡走：** 礼物就落在等待的人脚下，会被立刻拾起，于是“地上的礼物”找不到。检查改为地上有，或者背包里多了一颗。
- **失路叶鱼没有来：** 它只出现在有人 16 格内的窗外，而脚本走完花路就一直待在梦树旁。走完花路和围场后改为回到小木屋附近等待（游荡的梦种在那里也会绕着麦田游）。
- **第二颗梦种没被带到蹄印：** 它在第一颗落地时已经跟着花走了，而“带去蹄印”只处理还在漂的梦种；落下的梦种又被脚下立刻拾起，脚本数不到。改为按背包里梦种的数量计数，并且不论第二颗在做什么都送到蹄印旁。
- **梦种落得太慢：** 诊断输出显示一颗梦种 40 秒才下降 9 格，玩家要等一分多钟才够得着。现在下落快了数倍，落到手边的高度后停住等人引导。
- **客户端的蹄印缓存：** 蹄印在鹿之路确定时算一次，路的远端还没加载时用路的高度代替，之后不再重算。现在只要还有蹄印落在未加载的地面上，就每五秒重算一次。巨鹿模型本身在未加载处也用路的高度，检查改为只核对本客户端有地面的蹄子，并区分着地与抬起。

### 画面复查与修正

`-PtidePreview=art -PtidePreviewScenes=dream`（50 张），舞台是 QA 世界旁的一片花田。另写了 `.dev/art/dream_sky_view.py`：用 moderngl 离线运行真正的 `dream_sky.fsh`，几秒内出一张多视角对照图，与游戏里的画面一致，天空的大部分迭代都在这里完成。第一轮看到并修正：

- **树冠像细胞：** 最初的近处叶团是 Voronoi 单元，深色的心、发亮的边，看上去像显微镜下的蛙卵；生长前沿的“卷须”是 Voronoi 单元边，像一圈裂开的玻璃；落叶后的枝影也是同样的裂纹。现在是从下面看的树冠：在 3×3 邻域里取覆盖此处最高的一棵圆形树冠，树冠互相重叠、树与树之间留缝、有的地方没有树；轮廓由三级噪声碎成叶簇，按叶层厚度逆光着色；枝影是三到五根弯曲并分叉两次的枝条加一层细枝。树冠一棵一棵地长出、各自转成蜜金色、成片落下。第二轮又去掉了树冠里过多的白色透光点（像发霉）。
- **倒悬的树像棒棒糖、树根像筷子：** 挂下来的树冠是暗灰的光滑团块，树根是又直又黑的长杆。树冠轮廓改为按视角与叶簇噪声碎成叶边，逆光着色、亮度与天上的树冠一致，落叶前一起转金；树根改为大尺度 S 形加细小弯曲，粗根由两三股缠绕的长条编成，树皮是带苔藓的银灰色，并加上树冠的绿色环境光。
- **巨鹿像玻璃瓶、腿像折弯的吸管：** 身体里的 Voronoi 纹改为噪声脊线的叶脉与流动的薄雾，整体更实一些；腿在关节处用 Catmull-Rom 样条过渡；头改为宽阔的颅顶、细长的口鼻和深色鼻头；鹿角改为长着苔藓的活木，小树林更密更大，叶子碎边、逆光。
- **远处地形发白：** 雾色只向翡翠色混了六成，远景在绿色天空前成了白色剪影；原版云被抬高后越过了树冠，在地平线露出来。雾色改为与树冠地平线处的雾完全一致；森林长满后云直接隐去而不是抬高。
- **花纹画在崖底和墙上：** 花纹只按离中心的距离判断，会出现在悬空方块的底面和侧面。改为按深度重建的法线只画在朝上的地面上。
- **叶鱼看不见：** 叶鱼平躺着，从地面斜看过去只剩一条边，颜色又和树冠相近。现在每片叶子绕自己的游动方向转向镜头，个头更大、颜色更亮，白天也有一点光晕。
- **梦树的花像泼的颜料：** 蜜色花斑改为小点。
- 预览本身的问题：鱼群场景里的鱼群在拍摄前就游出了画面（改为原地游动）；失路叶鱼的镜头朝向屋里（改为从屋里看向窗外）；巨鹿侧面镜头落到舞台边缘外的低处，拍到舞台底面（改为不低于巨鹿脚下的高度）；围场场景手动写了状态却没有主人，服务端下一刻就按“主人不在”把它放掉，改用游戏里的 `openEnclosure` 打开，并且拍摄时不能是旁观模式。

### 画面复查与修正

开发客户端中四十余个 `hush_` 场景拍了三轮，逐张检查，发现并修正：

- **颜色细带在黑日升起的整段都看不见：** `ribbons()` 里写成了 `5 / 12`，Java 的整数除法得 0，平滑区间倒了过来，上行阶段恒为 0；只有倒流阶段可见。改为 `5 / 12.0`，并在 GameTest 里加了细带三段走向的断言。细带同时收细、加上缓慢的摆动，最低宽度按像素而不是 `fwidth`（循环里的导数在分支中未定义）。
- **云像咬了黑日一口：** 原版云画在天空之后，方块云挡在黑日前面。覆盖通道改为自己读深度，按高度和距离认出云的像素，在云上重画黑日与日冕；黑日成了"天上的洞"。
- **黑日发灰：** 颜色通道把天空像素也按提亮曲线处理，纯黑被抬到 0.17。天空改为只去色不提亮。
- **灯火把原色整片还原：** 小屋、花和草在火把旁完全是彩色的。改成旧照片般的棕黄，只透出一成原色；无声提灯、行列之灯和举灯透出更多（半成左右）；火把的范围也缩小。
- **灰潮从视距以外开始：** 前沿起点 520 格，普通视距下前一半根本看不见。起点改为 320 格，并按客户端视距缩放，灰潮总是从能看见的边缘漫进来；灰潮场景改为高处俯视，能看见起伏的边界和仍然有颜色的一圈。
- **世界不够苍白、全蚀不够白：** 提亮曲线改为 0.15 + 0.81·lum^0.8；全蚀时大地再漂白三成多。
- **天顶有一圈圈同心环：** 程序化天空里沿同一高度的卷云笔触，仰望时成了同心圆。卷云压到 20° 以下、每笔带倾斜、变淡；最高的层云带也降低变淡。
- **白线旁有一条虚线：** 白线的宽度取 `fwidth(atan(...))`，在身后方位角跳变一整圈的地方导数爆掉，画出一列断续的亮线（残像时是暗线）。改为对到白线的角距离取导数。
- **羽毛看不见：** 白色小羽毛在白色世界里消失，而且它不写深度，颜色通道读到的是它后面的墙，保色点对不上。改成一根松鸦的蓝羽（道具、罩中羽方块与图标一起），放大，并移到颜色通道之后绘制，保持原色。
- **行列永远看不到蚀：** 行列在 6.9/12 离场，而全蚀从 7/12 开始，"一齐停下仰望"根本不会发生。行列的出发窗口改到黑日升到半空之后（5.2/12–8.6/12），走到观者附近时正好赶上全蚀。
- **擦去只是整体变淡：** 碎屑从上往下落，外套却是均匀淡出。改为分段擦去：先是帽子，然后肩膀和袖子，最后下摆。
- **敲门的姿势拍不到、门装在墙外：** 预览里在外套已处于敲门状态时再设一次敲门，数值没变就不会同步，客户端的计时没有重置；现在同状态重设也会重新计时。预览小屋的门原先放在墙外一格，已放进墙里并朝外；外套站位也离门更近，伸出的袖子正好碰到门。
- **窗光看不见：** 门窗光柱原先在颜色通道之前加亮，被提亮曲线压平。移到颜色通道之后，成为室内唯一干净的白。
- **尘埃像远处的苍蝇：** 暗色小点改为浅色、更小更淡。行列更透明一些。
- 手记里只有一列的配方（静烛、星海的手记本身）改为放在网格中间一列。

- **腿是交叉的，这是模型错误。** 建模空间里正偏航会把左侧的腿转向后方，而脚本给左前腿写了正偏航：前髋的腿伸向后方、后髋的腿伸向前方，在身下交叉。动画按"前腿"编号去打结，动起来的正是伸向后方的那对腿。改正偏航符号后前腿朝前、后腿朝后；同时发现针脚尖离地约 0.2 格，把胫节角度从 -98° 调到 -126°，针尖正好着地。

**线灵。** 重跑完整流程时，QA 玩家在口袋收成残丝后被线灵啄死：三只线灵每 1.2 秒各啄一颗心，能持续半分钟，对"规模有限的一波"来说太致命。改为每下半颗心、间隔 1.8 秒，并在口袋收成残丝的同时散成线。完整流程新增一项检查，42 项全部通过；47 项 GameTest 在最终源码上全部通过。

编写测试时发现并修正了三个模组问题：

- 选门、选镜框位置、选裂片位置原先用 `canSeeSky` 判断露天。它基于天空光照，刚载入、光照还没算完的区块里会误判为"有顶"。改为按高度图判断。

### 天空接缝与天顶（同日第二次更新）
